## 1. 背景与定位

### 1.1 问题陈述

初中数学的日常教学循环是「布置作业 → 学生完成 → 教师批改 → 课堂讲评」。当前讲评环节存在三个结构性损耗：

1. **讲评内容靠经验拍脑袋**。教师依据自己批改时的印象决定讲哪几题，缺乏全班真实需求的量化输入。结果常见两类偏差：讲了大部分人已经会的题（浪费课堂时间），或漏讲了少数人卡死但没人举手的题。
2. **学生的困难无法低成本表达**。课堂上问「哪题不会」，举手的永远是固定几个人。「不会」在同伴面前是负面信号，大多数学生选择沉默，教师拿不到真实分布。
3. **困难的"类型"信息完全丢失**。即使知道 30 人选了第 7 题，"完全没思路"和"做出来了但想看更简洁的解法"是两种截然不同的教学需求，对应完全不同的讲评方式。现有工具（错题本、答题器）只统计对错，不采集**归因**。

同时，教师积累的教学资料（课件、教案、试卷）以文件形式散落，与知识点之间没有结构化关联，无法在需要时被精准调用。

### 1.2 产品定位

**一个部署在教室的课堂讲评决策系统。**

MathMate 不是题库、不是自动批改工具、不是学生自习 App。它只解决一个问题：**让教师在讲评前 5 分钟，知道今天这堂课该讲哪几题、为什么讲、重点讲什么。**

三条数据主线服务于这一个出口：

```
教学资料 ──→ [知识图谱]  ─┐
                          ├──→ [讲评决策] ──→ 教师
作业照片 ──→ [题目结构化] ─┤
                          │
学生宠物 ──→ [选题 + 归因] ┘
```

### 1.3 核心设计理念：宠物是心理保护层，不是游戏化糖衣

学习宠物在本产品中承担的是**功能性职责**，而非用户留存手段：

- **身份锚点**：大屏上 40 只宠物按座位排布，学生一眼认出自己的那只，无需登录输密码。
- **表达代偿**：交互文案是「你的宠物想听老师讲哪几题？」而不是「你哪几题不会？」。让学生以宠物之名表达困难，显著降低承认「我不会」的心理成本——这是本产品能否拿到真实数据的关键。
- **匿名聚合**：大屏公开视图只显示「12 只宠物想听第 7 题」和宠物剪影，**不显示姓名**。教师端才能下钻到具体名单。

明确的反面约束（写入需求，防止后续被"增长"需求带偏）：

- 不做全班公开排行榜（避免公开羞辱倒数学生）
- 不做付费道具、不做抽卡
- 投票窗口之外，宠物动画进入静默态，不得干扰课堂
- 宠物成长值不与「答对率」强绑定（否则弱生永远长不大），主要来源是**参与与订正**

| 层级 | 指标 | 基线 | 目标（试点一学期后） |
| --- | --- | --- | --- |
| 北极星 | 讲评命中率（教师所讲题目 ∩ 学生所选题目 / 教师所讲题目） | — | ≥ 70% |
| 参与 | 单次投票的班级参与率 | — | ≥ 85% |

| 质量 | 题目识别的教师校对修改率（衡量 OCR/标注质量） | — | ≤ 15% 的题目需要人工修改 |
| 质量 | 知识点自动标注准确率（教师抽检） | — | ≥ 90% |
| 留存 | 试点班级周活跃（每周使用 ≥ 3 天）教师占比 | — | ≥ 60% |

### 1.5 非目标（本期明确不做）

| 不做 | 原因 |
| --- | --- |
| 学生答卷的自动批改与对错判定 | 手写体 + 解题过程的判分是独立的大工程，风险极高。V2 评估。本期只做**题面**结构化 |
| 自动生成个性化练习/自适应推题 | 依赖长期掌握度模型，数据量不足时效果差且教师不信任 |
| 学生端自主刷题 / 家长端 | 会把产品拖成综合学习平台，稀释核心价值 |
| 数学以外学科 | 公式识别与知识图谱强学科绑定 |
| 教师直播/录课 | 与核心闭环无关 |
| 人脸识别登录 | 未成年人生物特征采集，合规风险不对等 |

## 2. 用户与角色

### 2.1 角色定义

| 角色 | 描述 | 主要触点 |
| --- | --- | --- |
| **学科教师** | 初中数学教师，核心用户。上传资料与作业、校对识别结果、查看讲评建议 | 教师端 Web / 移动端拍照 |
| **学生** | 7–9 年级学生，12–15 岁 | 教室大屏（主）、个人移动端（可选） |
| **教研组长** | 审核校本知识图谱、跨班对比数据 | 教师端 Web |
| **学校管理员** | 建班、导入花名册、分配教师权限、设备管理 | 管理后台 |
| **平台超管** | 维护课标知识图谱母版、租户管理 | 运维后台 |

### 2.2 关键场景

#### 场景 A：学期初，教师建立知识图谱（低频，一次性 + 持续补充）

> 王老师接手初二两个班。开学第一周，她在教师端选定「北师大版 · 八年级上册」，系统自动加载课标知识点骨架。她把自己攒了三年的课件（32 个 PPT）、单元教案和历年试卷批量拖进上传区。20 分钟后系统给出解析结果：识别出 47 个知识点、136 个资源片段挂载建议。她逐个确认，把系统误判的「勾股定理逆定理」归类修正，补充了两个自己总结的易错点。点击发布，校本图谱 v1 生效。

#### 场景 B：每日，教师上传作业（高频，每天 1 次）

> 周三晚 21:40，王老师在手机上打开 MathMate，对着明天要讲评的作业页拍了 3 张照片（一份 A4 卷，共 12 题），点上传，选择「初二(3)班 · 11月13日作业」。
> 约 40 秒后收到推送：12 题已识别。她点开校对页，发现第 9 题的图形没被切进来，手动框选补上；第 11 题的知识点被标成「一元二次方程」，实际考的是「二次函数与x轴交点」，她改正。第 5 题系统标注难度 4 星、易错点「忽略判别式为零的情况」，她认为准确，直接通过。全程 3 分钟，点击「发布到大屏」。

#### 场景 C：次日课前，学生在大屏选题（高频，每天 1 次）

> 周四第二节课前 8 分钟，初二(3)班的大屏亮起「宠物花园」，40 只萌宠按座位排布在场景里，顶部显示「今日作业 12 题 · 已有 9 位同学选好」。
> 小林走到大屏前，在座位图对应的位置点了自己那只蓝色的小老虎。老虎跳到前台，屏幕切换为题目卡片墙。他点了第 7 题、第 11 题。每点一题，弹出 6 个大图标的原因选择——他给第 7 题选了「完全没思路」，给第 11 题选了「做出来了，想看更简单的方法」。提交后老虎回到花园，头顶亮起一颗星。全程 22 秒。
> 大屏支持双人同时操作，屏幕左右分区，后面排队的同学同时在另一区操作。

#### 场景 D：上课时，教师拿到讲评建议（高频）

> 上课铃响，王老师在讲台平板上打开今日看板：
> - **第 7 题（优先级 1）**：19 人选，其中 14 人「完全没思路」。系统提示：该题考查「一元二次方程根与系数关系」，其前置知识点「配方法」在上周的作业中错误率也偏高，建议**从前置知识点回讲**。
> - **第 11 题（优先级 2）**：11 人选，但 8 人是「想看更简单的方法」。系统提示：多数学生已掌握，建议**只讲一题多解，控制在 3 分钟**。
> - **第 3 题（优先级 3）**：6 人选，5 人「做错了不知道错在哪」。系统关联到易错点「移项未变号」，并调出她学期初上传的课件第 12 页作为讲解素材。
> 她按这个顺序讲，跳过了原本打算讲的第 2 题（0 人选）。

## 3. 功能需求

需求编号规则：`FR-<模块>-<序号>`。优先级：**P0** = MVP 必须，**P1** = 首个正式版本，**P2** = 后续迭代。

### 3.1 模块一：知识图谱（KG）

#### 3.1.1 设计原则：预置骨架 + 校本挂载

**不采用「教师上传什么就生成什么图谱」的纯自动方案。** 理由：不同教师上传资料的覆盖度和质量差异极大，纯自动生成会导致每个班一个结构混乱、互不兼容的图谱，知识点无法跨班对比，前置关系也无法保证正确。

采用两层结构：

- **L1 课标母版（平台维护，只读）**：依据《义务教育数学课程标准（2022 年版）》构建，覆盖四大领域（数与代数、图形与几何、统计与概率、综合与实践），约 400–500 个知识点节点、约 2000 条关系。由教研专家 + 平台团队维护，全租户共享，学校不可修改。
- **L2 校本层（学校/教师维护，可写）**：教师上传的资料、题目、自定义易错点、自定义拆分的子知识点，**挂载**到 L1 节点上。教师可以扩展、可以标注，但不能破坏 L1 的骨架结构。

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| FR-KG-01 | 平台内置课标知识点母版，支持按教材版本（人教版/北师大版/苏科版/浙教版）与年级学期筛选 | P0 |
| FR-KG-02 | 教师批量上传教学资料，支持 PDF / DOCX / PPTX / 图片，单次 ≤ 50 个文件，单文件 ≤ 100MB | P0 |
| FR-KG-03 | 系统自动解析资料：文档切分 → 内容片段抽取 → 知识点识别 → 与 L1 母版节点对齐（消歧、同义词归并） | P0 |
| FR-KG-04 | 对齐结果以「建议」形式呈现，**必须经教师逐条确认或修改后方可入库**，禁止自动写入 | P0 |
| FR-KG-05 | 教师可手动新增校本知识点（挂在某个 L1 节点下作为子节点）、新增易错点、新增知识点间关系 | P0 |
| FR-KG-06 | 图谱可视化浏览：以领域/章节为入口，展示节点及前置、包含、相关三类关系，支持搜索定位与聚焦邻居 | P1 |
| FR-KG-07 | 图谱版本管理：每次发布生成新版本号，可查看变更历史、可回滚 | P1 |
| FR-KG-08 | 教研组长可将某位教师的校本层提升为「校级共享层」，同校教师复用 | P1 |
| FR-KG-09 | 资源片段与知识点关联后，可在讲评看板中被一键调出作为讲解素材 | P1 |
| FR-KG-10 | 知识点掌握度热力图：基于历史作业选题与归因数据，标注班级薄弱节点 | P2 |

#### 3.1.2 知识点节点必备属性

| 属性 | 说明 | 示例 |
| --- | --- | --- |
| `code` | 课标编码（L1）或校本编码（L2） | `A2-03-01` |
| `name` | 标准名称 | 一元二次方程根的判别式 |
| `aliases` | 同义词/俗称，用于对齐消歧 | ["判别式", "Δ", "delta"] |
| `domain` | 四大领域之一 | 数与代数 |
| `grade` / `semester` | 年级 / 学期 | 9 / 上 |
| `difficulty_base` | 基础难度 1–5 | 3 |
| `core_literacy` | 核心素养标签（多选） | ["运算能力", "推理能力"] |
| `exam_weight` | 中考考查权重 0–1，用于讲评优先级计算 | 0.8 |
| `status` | draft / reviewed / published | published |

#### 3.1.3 关系类型

| 关系 | 语义 | 用途 |
| --- | --- | --- |
| `PREREQUISITE_OF` | A 是 B 的前置知识 | 「完全没思路」时回溯该讲的起点 |
| `PART_OF` | A 从属于 B | 层级导航、难度聚合 |
| `RELATED_TO` | 横向相关 | 关联复习、变式推荐 |
| `COMMON_ERROR_IN` | 易错点属于某知识点 | 「做错不知道错哪」时的讲解锚点 |
| `METHOD_FOR` | 解题方法适用于某知识点 | 「想看更好方法」时的素材 |

### 3.2 模块二：每日作业解析

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| FR-HW-01 | 教师通过移动端拍照或 Web 上传作业**题面**照片，单次 1–10 张，自动按顺序拼接为一份作业 | P0 |
| FR-HW-02 | 上传时绑定：班级、作业日期、作业名称、（可选）关联章节 | P0 |
| FR-HW-03 | 图片预处理：自动纠偏、去阴影、裁边、增强对比度；预处理结果可预览并手动调整 | P0 |
| FR-HW-04 | 版面分析与题目切分：自动识别题号、切出每道题的图像区域（含题干、图形、选项） | P0 |
| FR-HW-05 | 内容识别：题干文本 + 数学公式（输出 LaTeX）+ 几何图形（保留为图像区域，不强求矢量化） | P0 |
| FR-HW-06 | 题目结构化：题型（选择/填空/解答/证明/作图）、题干、选项、分值 | P0 |
| FR-HW-07 | 知识点自动标注：每题关联 1–3 个知识点，带权重；标注结果必须可追溯到 KG 节点 | P0 |
| FR-HW-08 | 难度估计（1–5）、预估用时、易错点提示、解题要点（3–5 步骤纲要） | P1 |
| FR-HW-09 | **教师校对页**：逐题查看识别结果与原图对照，支持修改题干、重新框选图形区域、增删知识点标签、调整难度、合并/拆分题目、删除误识别题 | P0 |
| FR-HW-10 | 低置信度项高亮标记（如公式识别置信度 < 0.8 的片段标黄），引导教师优先校对 | P0 |
| FR-HW-11 | 校对完成后一键「发布到大屏」，未发布的作业不对学生可见 | P0 |
| FR-HW-12 | 题目查重：与本班历史题目比对，命中相似题时提示「与 10/22 作业第 5 题相似」 | P1 |
| FR-HW-13 | 支持从历史题库直接选题组卷，跳过拍照流程 | P1 |
| FR-HW-14 | 解析失败或超时的图片给出明确原因（模糊/光线不足/非作业内容），并提供重拍指引 | P0 |
| FR-HW-15 | 学生答卷照片的作答情况识别（对错标注） | P2（非目标，V2 评估） |

**关键约束**：识别结果在教师点击「发布」前，一律视为草稿。**系统不得在无人校对的情况下把内容推给学生。** 数学题目一个符号错误就会让整道题失去意义，这条约束不可妥协。

### 3.3 模块三：大屏宠物选题

#### 3.3.1 宠物系统

| 编号 | 需求 | 优先级 |

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| FR-VOTE-01 | 教师在教师端开启/关闭「投票窗口」，大屏据此切换待机态与投票态 | P0 |
| FR-VOTE-02 | 学生点击自己的宠物进入个人选题流；支持**座位号后两位**作为轻量二次确认，防止误点他人宠物 | P0 |
| FR-VOTE-03 | 题目卡片墙展示当日全部题目：题号 + 题干缩略图 + 知识点标签 + 难度星级 | P0 |

| FR-VOTE-06 | 支持撤销选择、重新提交（在投票窗口内） | P0 |

| FR-VOTE-08 | **多点触控分区**：大屏支持同时 2 人（≥86 寸支持 3 人）在独立分区操作，互不干扰 | P0 |
| FR-VOTE-09 | 单人操作全流程无键盘输入，全部为大按钮点击，目标 P50 ≤ 20 秒 | P0 |
| FR-VOTE-10 | 大屏公开视图**不显示学生姓名**，仅显示宠物形象与聚合数量 | P0 |
| FR-VOTE-11 | 移动端并行投票通道：学生扫码或用班级码在手机上完成同样流程，与大屏数据合并 | P1 |
| FR-VOTE-12 | 支持「无补充需求」快捷提交（一键表示今天没有想听的题），用于区分「不想选」与「没来得及选」 | P1 |
| FR-VOTE-13 | 投票窗口关闭后展示班级聚合结果动画（题目热度条形图 + 原因分布） | P1 |

#### 3.3.3 归因选项（产品核心资产）

原因不是自由文本，而是固定枚举——因为要能聚合、能驱动讲评策略。每个选项配大图标 + 短语，学生 3 秒可选。

| 编号 | 学生看到的文案 | 内部编码 | 教学含义 | 讲评策略映射 |
| --- | --- | --- | --- | --- |
| 1 | 完全没思路，不知道从哪下手 | `NO_IDEA` | 前置知识缺失 | 沿 KG 回溯前置知识点，从更早的地方讲起 |
| 2 | 有点思路但中间卡住了 | `STUCK_MIDWAY` | 关键步骤断裂 | 定位卡点步骤，重点讲那一步的转折 |
| 3 | 做错了，但不知道错在哪 | `WRONG_UNKNOWN` | 存在错误概念 | 调出该知识点的易错点，做错因剖析 |
| 4 | 会做，但太慢/太麻烦 | `SLOW` | 方法不优 | 讲解优化路径与计算技巧 |
| 5 | 做对了，想看有没有更好的方法 | `WANT_BETTER` | 已掌握，求提升 | 一题多解，控制时长 |
| 6 | 想看这类题的变式和拓展 | `WANT_EXTEND` | 学有余力 | 变式训练，可放课后 |
| 7 | 就是算错了（粗心） | `CARELESS` | 非知识性问题 | 一般不占用讲评时间，计入个人提醒 |

学生可对同一题额外附加一句话说明（可选，≤30 字，语音转文字或快捷短语），供教师参考。

### 3.4 模块四：讲评决策（数据出口）

前三个模块采集的数据必须有出口，否则整个系统对教师没有价值。这是**必做模块**，非可选项。

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| FR-DEC-01 | 今日讲评看板：题目按计算出的**讲评优先级**排序，展示选择人数、原因分布、涉及知识点 | P0 |
| FR-DEC-02 | 每题给出**讲评建议**：为什么要讲（主导原因）、重点讲什么（策略映射）、建议时长 | P0 |
| FR-DEC-03 | 优先级权重可由教师调整（如更看重「完全没思路」的人数），支持保存为个人偏好 | P1 |
| FR-DEC-04 | 下钻查看：某题选择「完全没思路」的具体学生名单（仅教师可见） | P0 |
| FR-DEC-05 | 关联素材：自动调出与该题知识点关联的、教师自己上传的资源片段 | P1 |
| FR-DEC-06 | 讲评记录：教师标记「已讲」，用于计算讲评命中率与避免重复讲 | P1 |
| FR-DEC-07 | 周报/月报：班级知识点薄弱分布、高频归因趋势、参与率统计 | P1 |
| FR-DEC-08 | 「零人选择但客观重要」的题目单独提示（避免学生集体误判简单题） | P1 |

### 3.5 通用：账号、班级、权限

## 4. 非功能需求

### 4.1 性能

| 指标 | 要求 |
| --- | --- |
| 大屏首屏加载 | ≤ 2s（本地缓存命中时 ≤ 800ms） |
| 大屏触摸响应 | ≤ 100ms |
| 大屏动画帧率 | ≥ 50fps（40 只宠物同屏） |
| 作业照片解析（单张 A4，约 8–12 题） | P50 ≤ 25s，P95 ≤ 45s |
| 教学资料解析（单个 30 页 PPT） | P95 ≤ 90s |
| 投票提交到教师端看板更新 | ≤ 1s（WebSocket 推送） |
| 教师端页面交互 | P95 ≤ 500ms |

### 4.2 容量与并发

- 单租户（学校）规模：≤ 100 个班级、≤ 5000 名学生、≤ 300 名教师
- 峰值并发：**同一时段 50 个班级同时进入投票窗口**（课前 10 分钟是明显的尖峰）
- 单班题目量：单次作业 ≤ 30 题
- 存储：单校年增量约 500GB（作业照片为主）

### 4.3 可用性与降级 ⚠️ 高优先级

学校网络环境不稳定是**必须正面处理的常态**，不是异常。

| 编号 | 需求 |
| --- | --- |
| NFR-AV-01 | 大屏在投票窗口开启时预拉取并本地缓存当日全部题目数据与图片 |
| NFR-AV-02 | 网络中断时，大屏**仍可完成完整投票流程**，投票记录写入本地 IndexedDB |
| NFR-AV-03 | 网络恢复后自动增量同步离线投票，冲突以「同一学生最后一次提交」为准 |
| NFR-AV-04 | 大屏顶部常驻网络状态指示，离线时显示「离线模式 · 数据将稍后同步」 |
| NFR-AV-05 | 大屏应用崩溃后 5 秒内自动重启并恢复到投票态，不丢失已提交数据 |
| NFR-AV-06 | 后端服务可用性 ≥ 99.5%（上课时段 7:00–18:00 内 ≥ 99.9%） |
| NFR-AV-07 | LLM 服务不可用时，作业解析降级为「仅切题 + 教师手动录入」，不阻断主流程 |

### 4.4 兼容性

- 大屏：教室交互一体机，Android 9+ / Windows 10+，分辨率 1920×1080 与 3840×2160，触控点 ≥ 10 点
- 教师端：Chrome / Edge 最近两个大版本；移动端 iOS 15+ / Android 10+
- 大屏使用 Chromium 内核 WebView 运行，需明确最低内核版本（Chromium 90+）

### 4.5 可维护性

- 所有 LLM 调用的 prompt 与模型版本可配置、可灰度，并记录于解析任务元数据，保证结果可复现与可追责
- 识别管线各阶段产物（预处理图、切题框、OCR 原始输出）保留 30 天，用于问题排查与效果迭代
- 教师的每一次校对修改都作为**标注数据**沉淀，用于后续模型评测与优化（需在隐私政策中说明）

## 5. 数据、隐私与合规

**用户主体为未成年人，合规要求高于普通 To B 产品。**

| 编号 | 要求 |
| --- | --- |
| PRIV-01 | 遵循《个人信息保护法》《未成年人保护法》《未成年人网络保护条例》，学生个人信息处理须取得监护人同意，由学校统一采集并留存同意记录 |
| PRIV-02 | **不采集人脸、指纹、声纹等生物识别信息**（语音补充说明功能须本地转文字后丢弃音频，或直接取消该功能） |
| PRIV-03 | 学生信息最小化：仅存储姓名、班级、座位号、学号。不采集身份证号、手机号、家庭住址 |
| PRIV-04 | 大屏公开显示区域一律使用宠物昵称，**不出现学生真实姓名** |
| PRIV-05 | 作业照片默认保留 1 学年，到期自动删除；学校可配置更短周期 |
| PRIV-06 | 学生归因数据（尤其是「完全没思路」）属敏感教学数据，仅任教教师与教研组长可见，不对其他学生、其他班级教师开放 |
| PRIV-07 | 数据所有权归学校；支持学校发起的数据导出与彻底删除（含备份） |
| PRIV-08 | 教学资料上传需教师确认拥有使用权；对疑似受版权保护的教辅材料，仅做知识点抽取，不做全文留存与分发 |
| PRIV-09 | 若使用第三方 LLM 服务，需在隐私政策中披露；作业照片与学生数据传输前须去除可识别学生身份的信息 |
| PRIV-10 | 支持私有化部署形态，满足对数据不出校的学校要求 |

## 7. 风险

| 风险 | 影响 | 缓解措施 |
| --- | --- | --- |
| **大屏吞吐不足**：40 人 × 20s ÷ 2 分区 ≈ 7 分钟，接近课前可用时间上限 | 高 | ① 投票窗口提前至上一节课下课就开放（约 15 分钟）；② P1 上线移动端并行通道；③ 大屏 ≥86 寸支持 3 分区；④ 允许部分学生不参与，不强制 100% |
| 手写数学公式与几何图形识别质量不达标 | 高 | M0 阶段先验证再投入；教师校对为强制环节兜底；几何图形不做矢量化，直接保留图像区域 |
| 教师嫌校对麻烦，放弃使用 | 高 | 校对页优化到 3 分钟内完成；低置信度高亮减少全量检查；历史题库复用降低重复劳动 |
| 学生把选题当游戏，随意乱选 | 中 | 上限 3 题强制取舍；教师端可见异常模式（如某生每天全选）；宠物能量不因选题多而增加 |
| 知识点自动标注错误，污染图谱与统计 | 中 | 强制教师确认；标注可追溯可回滚；持续用教师修改数据评测模型 |
| 学校网络不稳定导致课堂事故 | 高 | 离线优先架构（NFR-AV-01~05），断网必须可用 |
| LLM 调用成本超预算 | 中 | 结果缓存与题目查重避免重复解析；分级调用（简单题用小模型）；成本监控与配额 |
| 未成年人数据合规问题 | 高 | 见第 5 章；上线前做合规评审；优先支持私有化部署 |
