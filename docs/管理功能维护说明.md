# 管理功能维护说明

本版补齐：
- 后端统一拒绝教研组长的业务写操作（个人改密除外），不依赖页面隐藏按钮。
- 学生「删除」改为停用，保留学生、宠物、选题、提交记录；维护记录页面可恢复。当前停用学生的座位和学号仍保留，避免在缺少学籍时间线时错误复用。暂未实现转班、毕业、班级归档。
- WebSocket 每次广播前复核权限，空闲连接每 2 秒复核。停用、改密、任教权限变动和设备解绑后，旧连接停止接收并关闭。仍为单 worker 模式。
- 教师仅改姓名不撤销登录；账号、角色、状态、班级权限改变仍撤销。
- 管理日志与业务事务同时提交，记录教师、任教关系、班级、学生、大屏的变更，不记录密码哈希、密码、设备令牌或配对码。仅学校管理员可查看本校日志。上线前的操作无法补录。
- 账号管理、班级管理、维护记录页面共用凭据续期逻辑。

## 数据库选择

当前是同机 SQLite WAL，单进程试用可继续使用。准备多班级同时长期使用、多应用进程或多机器运行时，优先迁移 PostgreSQL。MySQL 也能满足账号、班级、作业等关系型数据需求，但原有设计及 data/l1_seed.sql 使用 PostgreSQL；选择 PostgreSQL 可以减少转换工作。

本次未切换数据库，也未宣称已验证 MySQL/PostgreSQL 兼容性。正式迁移需要引入版本化迁移（Alembic），检查约束、JSON、时间、索引和历史数据，执行全量迁移、核对行数与关联、演练回滚，再切换连接配置。SQLite 数据库、WAL、上传文件都必须纳入备份；运行中的 SQLite 备份使用 sqlite3 backup API，不只复制 .db 文件。

SQLite 官方说明：https://www.sqlite.org/whentouse.html
PostgreSQL 备份说明：https://www.postgresql.org/docs/current/backup.html
