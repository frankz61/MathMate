# apps/ —— 作业录入 + 大屏宠物选题闭环

对应 PRD 模块二（FR-HW-\*）、模块三（FR-PET-\* / FR-VOTE-\*）与 DESIGN §3.4、§5、§9。

```
apps/
  api/       FastAPI + SQLAlchemy 后端(含 26 条回归测试)
  screen/    教室大屏(学生端,免构建原生页面)
  teacher/   教师控制台:作业录入 / 讲评看板 / 学生与宠物
```

## 教师端三个页签

| 页签 | 做什么 |
| --- | --- |
| **作业录入** | 新建作业 → **拍照识别**或粘贴文本切题 → 自动挂知识点候选 → 逐题校对 → 发布到大屏 |
| **讲评看板** | 开窗/关窗、实时聚合（人数 × 归因权重排序）、点行展开学生名单 |
| **学生与宠物** | 全班宠物花名册、能量与提交次数、从未提交名单 |

## 照片识别（FR-HW-04/05）

`app/llm.py` → `recognize_problems()`。多模态模型直接读作业照片，输出题号、题型、
题干（数学式转 LaTeX）、选项、难度、是否含几何图形。多页作业逐张上传依次追加。

三条硬约束写在代码里，不靠提示词：

- **识别结果一律 `review_status="auto"`**，未逐题校对无法发布（FR-HW-11）。
  模型识别得再好也不例外 —— 数学题一个符号错就毁掉整道题。
- **原图始终保存**，无论识别成功与否。识别失败时原图就是唯一的降级依据。
- **任何失败都降级为 200 + 说明**，不抛 5xx。超时、限流、返回垃圾，
  教师的录入流程都不能被模型中断（NFR-AV-07）。

看不清的字模型会用 `⬚` 占位而不是猜测填补；含几何图形的题会计入 `with_figure`
提示教师 —— 图形本身无法被文本还原，这类题必须对照原图校对。

## 知识点标注

`app/kg_index.py`（检索）+ `app/llm.py` → `rerank_kp()`（可选重排）。
**只在 L1 母版的 141 个知识点里做选择，永不发明新知识点**（DESIGN §5）。

这条约束由**结构**保证而非提示词：候选恒由检索产生，LLM 只返回候选里的 id，
越界的返回值在 `llm.rerank_kp` 和 `authoring._annotate_batch` 两处各拦一次。
编一个「二次函数的对称轴性质」这种听起来很对但不在母版里的知识点，
会污染整个图谱统计。

检索部分三路证据加权：

1. **词根命中** — 题干里原样出现「分式」「一次函数」这类考点词根
2. **术语相似** — 与知识点画像（名称 ×3 + 描述 + 章节）的字符二元组相似度
3. **近邻投票** — 与 288 道**已标注真题**的相似度检索，用邻居标签投票

公式结构（`\frac` / `\angle` / `\odot` …）会被抽成带 `zz` 前缀的伪词，只参与题目之间的比对，**不冒充知识点名称**——早期版本把 `\frac` 直译成「分式」，结果一道问「哪个是分式」的题反被一堆含分数线的实数题带偏。

### 实测:LLM 重排并不比检索更准，所以默认关掉了

288 道已标注真题上的留一法对比（`python scripts/llm_eval_kp.py --n 0`，会真实计费）：

| 指标 | 检索 | 检索 + LLM 重排 |
| --- | --- | --- |
| top-1（全体 287 题） | **47.7%** | 42.2% |
| 章节 top-1（全体） | **63.4%** | 61.0% |
| top-1（只看模型愿作答的 240 题） | 52.1% | 50.4% |
| 〔天花板〕金标落在 top-8 候选内 | **72.1%** | — |

Wilson 95% 区间在同一子集上几乎完全重叠（45.8–58.3% vs 44.1–56.7%），
即**测不出差异**。模型在 16% 的题上弃权（其中 12 道检索本可答对），
纠正了 33 道、带偏了 37 道，基本相抵。

所以 `MATHMATE_LLM_RERANK_KP` **默认为 0**：花钱、变慢、没有可测得的收益，
三者同时成立时不应该默认开启。真正的瓶颈是**检索召回**——
金标压根不在 top-8 候选里的占 28%，重排再聪明也够不着。

两点诚实的保留：

- 金标本身有噪声。例如「一个凸多边形剪去一个角后内角和是 2520°」，
  语料标的是「三角形的内角和与外角」，模型选的「多边形的内角和与外角和」
  明显更对，却被算作「带偏」。这类噪声会低估重排，但「基准不准」
  正是让坏改动蒙混过关的常用借口，所以只作为注记，不作为开启的理由。
- 教师在校对页单题点 **「✨ AI 重推」** 不受此开关影响，且实测有用：
  上面那道分式题检索给的是「分式的运算」，点一下改成「分式的概念与基本性质」，
  并给出理由「考查分式的识别，属概念题」。人主动求助、结果当场可判，
  与批量默认自动跑是两回事。

检索基线单独复现（不打网络、不计费）：`cd apps/api && python -m app.kg_index --eval`

命中按**标签集合**判定（同一道题可能合法归属多个知识点）。

**这仍然是候选推荐，不是自动标注。** PRD FR-HW-07 的目标是 ≥90%，差距明显。
瓶颈是标注语料只有 288 条、覆盖 141 个知识点中的 69 个；典型失败是题干几乎全是公式、
没有中文关键词的题（如「计算 √12−√3」）。提升路径是补语料以抬高召回天花板，
而不是换更强的重排模型。教师逐题校对是强制闸门，正是为此存在。

## 与设计文档的三处偏离

首个切片的刻意取舍，都不是疏忽：

| 项 | DESIGN 规划 | 当前实现 | 影响 |
| --- | --- | --- | --- |
| 数据库 | PostgreSQL + pgvector + RLS | SQLite | 零配置可跑；schema 保持 PG 兼容（字符串 UUID、JSON 代替 ARRAY）。**RLS 租户隔离未实现** |
| 大屏 | React + Vite + PixiJS | 原生 ES 模块 | 免构建、便于逐条验证；API 契约已固定，迁移是机械工作 |
| 模型编排 | 版面分析 / 公式识别 / 知识点标注分别调用 | 单次多模态调用完成前两项 | 一页作业一次调用（约 15–30s），少一次往返；知识点仍走本地检索 |

未配 `MATHMATE_LLM_API_KEY` 时自动退回 **NFR-AV-07 降级路径**（仅切题 + 教师手动录入，
不阻断主流程），上传原图明确返回 `recognition.status = "unavailable"`，
界面上也会换成「上传原图（仅留存）」——**不假装识别成功**。

## 已实现的约束

这些是 PRD 里标注「不可妥协」的规则，均有测试覆盖：

- **大屏 bootstrap 不下发学生姓名**（FR-VOTE-10）—— 姓名会把「我不会」变成公开信号
- **选题上限服务端强制**（FR-VOTE-04）—— 只靠前端拦不住手机端/脚本
- **归因限定七类枚举**（PRD §3.3.3）—— 自由文本无法聚合
- **未发布的作业不能开窗**（FR-HW-11）—— 未经教师校对不得推给学生
- **能量与答对率无关，且重投不重复发放**（FR-PET-05）—— 否则弱生宠物永远长不大
- **幂等 + 乱序补传**（NFR-AV-03）—— 离线队列会重复、会乱序
- **断网可完整投票**（NFR-AV-02）—— 提交先落 IndexedDB，恢复后自动补传
- **主导归因按「人数 × 归因权重」**（DESIGN §7.1）—— 3 个「完全没思路」压过 5 个「粗心」
- **未逐题校对不能发布**（FR-HW-11）—— 发布接口硬拦，返回 409 与待校对题号
- **知识点只能选自 L1 母版**（DESIGN §5）—— 教师手选非法 id 返回 422
- **已发布的作业冻结**（改题会让题面与已投的票对不上）—— 需先撤回，投票中不允许撤回
- **题号连续无空洞**（大屏上是学生的定位锚点）—— 删题后两阶段重排，避开唯一约束；
  识别时丢掉空题也按剩下的重编号，不留洞
- **宠物花名册不做能量排行**（FR-PET-06）—— 按座位号排序；公开排行榜会变成对倒数学生的羞辱
- **模型不得发明知识点**（DESIGN §5）—— 候选集外的 `kp_id` 两处各拦一次，退回检索结果
- **模型说「候选都不对」时清空标注**而不是硬塞一个 —— 空标注会标黄逼教师手选，
  错标注则可能被顺手确认
- **LLM 失败一律降级为 200 + 说明**（NFR-AV-07）—— 超时/限流/返回垃圾都不能中断录入
- **降级必须让教师看见** —— 悄悄退回检索结果比不降级更糟
